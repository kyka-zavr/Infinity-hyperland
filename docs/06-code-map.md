# Карта кода Hyprland v0.56.2 для Infinity

Статус: первичный разбор (2026-10-22). Это результат чтения кода, а не проверенных экспериментов. Места, где нужна проверка, помечены.

Пути указаны относительно `hyprland/src/`.

## Главное наблюдение

В v0.56 раскладки уже сделаны подключаемыми внутри ядра:

- `layout/algorithm/Algorithm.hpp` (`CAlgorithm`) соединяет два алгоритма на рабочий стол: тайловый (`ITiledAlgorithm`) и плавающий (`IFloatingAlgorithm`). Окна делятся на тайловые и плавающие списки.
- `layout/space/Space.hpp` (`CSpace`) — пространство одного рабочего стола с рабочей областью (`workArea`) и списком целей.
- `layout/supplementary/WorkspaceAlgoMatcher.hpp` регистрирует алгоритмы по имени (`registerTiledAlgo`, `registerFloatingAlgo`) и выбирает алгоритм для стола.
- Готовые тайловые алгоритмы: `dwindle`, `master`, `monocle`, `scrolling`. Плавающий: `floating/default`.
- Интерфейс алгоритма (`layout/algorithm/ModeAlgorithm.hpp`): `newTarget`, `movedTarget`, `removeTarget`, `resizeTarget`, `recalculate`, `swapTargets`, `moveTargetInDirection`, `layoutMsg`. Для плавающих ещё `moveTarget` и `setTargetGeom`.
- Окно в layout представлено `ITarget` (`layout/target/Target.hpp`), у цели есть `position()`, флаг `floating()`, запоминание `lastFloatingSize()` и `wasTiling()`.

Вывод: режим Infinity естественно оформить как новый алгоритм в этой системе, а не как внешний плагин.

## Что придётся писать

1. **Алгоритм Infinity.** Хранит для каждой цели координаты на плоскости. Принимает `newTarget` (открытие по центру видимой области), двигает цели, меняет размер.
2. **Вид (view) стола.** Сдвиг и масштаб, общие для всех мониторов. Каждый монитор показывает свой прямоугольник общей плоскости (в соответствии с физическим расположением).
3. **Общая плоскость на нескольких мониторах.** Сейчас стол привязан к одному монитору (`CSpace` и рабочая область монитора). Нужно решить, как плоскость обслуживает несколько мониторов. Это самая рискованная часть, требует отдельного разбора.
4. **Переключение режима стола** (`MOD + SHIFT + SPACE`) на всех мониторах, с сохранением тайловых позиций и подбором ближайшего места при обратном переходе.
5. **Рендер с видом.** Применять сдвиг и масштаб ко всем окнам и слоям, где это нужно (панели и обои оставить как есть).
6. **Ввод с видом.** Преобразование координат курсора в координаты плоскости для хит-тестов, фокуса, перетаскивания и ресайза.
7. **`ALT + TAB` с центрированием** и **оверлей с живыми превью** для всех столов. Оверлей — новая подсистема рендера и ввода.
8. **Привязки:** `MOD + ЛКМ` (окно), `MOD + ALT` (весь стол), `CTRL + колесо` (зум), `MOD + SHIFT + SPACE` (режим), `ALT + TAB`.

## Основные риски

- Общая плоскость на несколько мониторов (пункт 3): архитектурно стол привязан к монитору.
- Хит-тесты и ввод при масштабе: в коде много мест, где координаты считаются напрямую по положению окна.
- Совместимость со слиянием upstream: чем меньше трогаем существующие файлы и чем больше кладём в новые, тем легче обновляться.
- Протокольные клиенты (layer-shell, lock screen) не должны попадать под зум и сдвиг стола.

## Предлагаемый порядок

1. Алгоритм Infinity на одном мониторе: окна на плоскости, перемещение `MOD + ЛКМ`, сдвиг всего стола `MOD + ALT`. Без зума.
2. Переключение режима и сохранение позиций.
3. Зум и пересчёт ввода.
4. `ALT + TAB` с центрированием.
5. Общая плоскость на несколько мониторов.
6. Оверлей с превью.

Каждый шаг проверяем во вложенном окне (`dev/run-nested.sh`).
