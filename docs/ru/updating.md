# Обновление на новые версии Hyprland

[English](../en/updating.md) | [Русский](updating.md)

База форка записана в файле [UPSTREAM](../../UPSTREAM) (тег и коммит оригинала). Текущая база: **Hyprland v0.57.0**.

## Как это устроено

- Ветка `upstream` хранит **только чистые импорты** оригинала, один коммит на версию. Наш код там не появляется.
- `scripts/sync-upstream.sh [тег]` делает новый импорт и вливает его в ветку `sync/<тег>`, созданную от `main`. Общая база слияния — прошлый импорт, поэтому конфликтовать могут только файлы, которые мы сами меняли.
- Закрепления подпроектов (`scripts/subprojects.pins`) обновляются по ссылкам на подмодули оригинала; подпроект, который оригинал убрал, удаляется из закреплений.
- `main` скрипт никогда не меняет. Результат собирается, проверяется руками (`dev/run-nested.sh`) и вливается через pull request.
- `.github/workflows/upstream-sync.yml` раз в сутки проверяет новый стабильный релиз: чистое слияние даёт ветку, проверочную сборку на Arch и pull request; конфликты открывают issue со списком файлов. Для автоматических pull request в настройках репозитория должен быть включён пункт «Allow GitHub Actions to create and approve pull requests».
- Библиотеки (hyprutils, aquamarine, hyprlang и др.) берутся из системы. Новому Hyprland могут понадобиться новые версии или новые библиотеки: при каждом обновлении сверяйте `installer/arch-deps.txt` с пакетом `hyprland`.

## Ручное обновление

```sh
scripts/sync-upstream.sh v0.58.0      # создаст sync/v0.58.0; при конфликтах остановится
git status                            # список конфликтов
# решить, git add, git commit
cmake --build build                   # поправить изменения API, о которых скажет компилятор
dev/run-nested.sh                     # проверить Infinity, зум, переключатель
git switch main && git merge --ff-only sync/v0.58.0
```

Затем сделать релиз (ниже).

## Сколько стоит обновление

Эталон — обновление с 0.56.2 на 0.57.0: в оригинале изменилось 718 файлов, конфликтовало 12 (ввод и клавиши переехали в `keybinds/`, окна разбиты на `desktop/view/window/*`, рендер перешёл на `Render::CRenderContext`, у рабочих столов появился `space()`, изменились библиотеки). Наш код в новых файлах не конфликтует никогда; точки встраивания перечислены в [architecture.md](architecture.md). Держите хуки маленькими, чтобы обновления оставались дешёвыми.

## Релизы

Схема версий: `v<версия Hyprland>-infinity.<n>`, например `v0.57.0-infinity.1`. Номер растёт с нашими собственными изменениями на той же базе Hyprland и сбрасывается в 1 при новой базе.

В описании каждого релиза две части: **что добавлено** (из [CHANGELOG.ru.md](../../CHANGELOG.ru.md)) и **версии использованных исходников** (база Hyprland, библиотеки, подпроекты). Вторая часть генерируется:

```sh
scripts/release-notes.sh              # печатает таблицу версий в Markdown
```

Порядок:

1. Обновить `CHANGELOG.md` и `CHANGELOG.ru.md` (новый раздел сверху).
2. `git tag -a v0.57.0-infinity.2 -m "..."` на `main`, `git push origin main v0.57.0-infinity.2`.
3. `gh release create v0.57.0-infinity.2 --title "..." --notes-file <файл>`, где в файле раздел из changelog плюс вывод `scripts/release-notes.sh`.
